## פרוצדורת סשן (מדויקת)

1. שחזור סביבה: clone + `npm ci` + `npm run build:packages` (חבילות נדרשות לבדיקות).
2. קריאת מצב: `CHECKLIST.md` (שורת "מצב") + רשומת השלב האחרון ב־`WORKLOG.md`.
3. בדיקת CI של הדחיפה הקודמת (Actions בגיטהאב) — אם אדום: תיקון ה־CI הוא המשימה
   הראשונה (תקדים: סבבי "תיקון CI" מתועדים ב־WORKLOG).
4. ביצוע השלב הבא לפי התכנית: מימוש ← בדיקות חדשות ← מאמת שלב ← עדכון
   WORKLOG/CHECKLIST ← בדיקות מהירות מקומיות.
5. commit (תבנית: `שלב <N>/100 — <כותרת> (M#)` + תוצרים + בדיקות שרצו) ←
   push ל־main ← ה־CI וה־Deploy (פייג'ס) מופעלים ← **לא לחכות** ← עדכון קובץ זה.
6. חוקי הריפו נאכפים אוטומטית: הקוד הישן לא נערך (כלל 8 — `verify-work-conventions`),
   נעילת ספירת הבדיקות ב־ci.yml (כרגע **1226**), אין החלשת בדיקות, אין עדכון golden
   אוטומטי, commit בלי layoutHash-diff רק לשינוי שאינו מנוע.
