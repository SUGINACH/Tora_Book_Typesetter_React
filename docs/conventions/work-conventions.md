## א. WORKLOG.md — מבנה רשומה מחייב

כל שלב בתכנית מתועד ברשומה אחת בפורמט הבא (זהו הפורמט שנהוג משלב 1):

```markdown
### שלב <N> — <כותרת השלב> (<אבן דרך M#>) — הושלם <תאריך>
- **תוצרים:** רשימת הקבצים/ה-artifacts שנוצרו, עם המספרים החשובים (כמות, גודל, ספירות).
- **פקודות בדיקה שרצו (ירוק):** פקודה מדויקת + תוצאה (כמה בדיקות, קוד יציאה).
- **ממצאים:** חריגות, תגליות, החלטות שהתקבלו במהלך השלב.
- **layoutHash diff:** <ישן> → <חדש> + סיבת השינוי + ממצאי audit   ← חובה משלב 33 ואילך, לכל שינוי מנוע
```

כללים:
1. רשומה נכתבת **רק אחרי** שהבדיקות רצו ועברו — לא מראש.
2. פקודת הבדיקה נכתבת כפי שרצה בפועל, כולל גרסת ה־Node.
3. רשומות היסטוריות לפני הפעלת התכנית נשמרות תחת הכותרת "לפני הפעלת התכנית" ואינן נערכות.

## ב. CHECKLIST.md — עדכון לפי יכולת מאומתת בלבד

1. תיבת שלב מסומנת ✅ **רק** כששער המעבר שלו ירוק, עם תאריך והפניה לרשומת ה־WORKLOG.
2. אין סימון "לפי תקווה" (אפיון §23.5): כל סימון מגובה בפקודת בדיקה שרצה וב־artifact שהופק.
3. עדכון שער אבן דרך (M0…M12) — רק כשכל שלביו הושלמו ואומתו.

## ג. GLOSSARY.md — מילון חי

1. מושג נוסף/משתנה **בפועל** → עדכון המילון באותו commit (אפיון §23.4): שם ייחודי, הגדרה קצרה, קוד/נתיב מקושר.
2. אין כפילויות שמות; מושג שמוחלף מסומן "הוצא משימוש ← <המושג החלופי>".
3. הגדרה ללא קוד קיים מסומנת "(עתידי)" עד למימוש — ואז מתעדכנת באותו commit.
